## 0. 部署架构总览

```
浏览器
  │  http://域名或公网IP:80
  ▼
Nginx（80 端口）
  ├─ 静态文件 dist/                    → 前端页面
  ├─ /api/*      → 转发 127.0.0.1:8080 → Java 后端
  └─ /uploads/*  → 转发 127.0.0.1:8080 → 图片
Java 后端（Spring Boot jar，监听 8080）
  │
  └─ 127.0.0.1:3306 → MySQL（cloud_notepad 库）
```

**关键原则：公网只开 80（和 443）端口，8080 和 3306 不对公网开放**，全部走服务器内部转发。

---

## 1. 三种部署方案

| 方案 | 说明 | 成本 | 适合 |
| --- | --- | --- | --- |
| **A. 本机 Windows + Nginx** | 用 Nginx 托管前端 + 反代后端，流程与真上线一致 | 免费 | 首次练手 |
| **B. 云服务器 Linux** | 购买 VPS，公网可访问；MySQL/Nginx 装在宿主机 | 几十元/月 | 独立服务器 |
| **C. Docker 部署** | 服务器上已有 Docker，用容器跑前后端 | 同上 | **服务器上已有其他 Docker 服务时** |

推荐顺序：先在本机 Windows 完整跑一遍（第 2 节），熟练后再上云（第 3 或第 4 节）。

> **怎么选 B 还是 C**：如果服务器是干净的（没跑别的服务），B 更简单，照着敲就行。
> 如果服务器上**已经跑着别的 Docker 栈**（尤其是已有的 MySQL），选 C——可以复用那个 MySQL，
> 不用再起一个数据库实例，在 2G 内存以下的小机器上这一点很关键。详见第 4 节。

## 2. 方案 A：本机 Windows + Nginx（练手）

### 2.1 前置条件

- MySQL 8 已启动，`cloud_notepad` 库已建好；
- 已装 Maven（`mvn -v` 正常）与 Node/npm。

### 2.2 安全配置外置（已完成，部署前只需准备值）

`backend/src/main/resources/application.yml` **已经全部使用环境变量占位符**，代码里没有任何明文密钥，无需再改配置文件：

```yaml
spring:
  ai:
    dashscope:
      api-key: ${AI_DASHSCOPE_API_KEY}
  mail:
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
  datasource:
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
jwt:
  secret: ${JWT_SECRET}
```

**部署前要做的是把变量的值准备好。**

#### 必填（缺任意一个，应用会因占位符无法解析而启动失败）

| 变量 | 说明 |
| --- | --- |
| `AI_DASHSCOPE_API_KEY` | 阿里云百炼 API Key |
| `MAIL_USERNAME` | 发件邮箱地址（QQ 邮箱） |
| `MAIL_PASSWORD` | QQ 邮箱 **SMTP 授权码**（不是邮箱登录密码） |
| `DB_USERNAME` | MySQL 用户名 |
| `DB_PASSWORD` | MySQL 密码 |
| `JWT_SECRET` | JWT 签名密钥，建议 32 字符以上随机串 |

#### 可选（不设则用括号里的默认值）

| 变量 | 说明 |
| --- | --- |
| `NOTEPAD_UPLOAD_DIR` | 图片保存目录。默认 `./uploads`，相对**后端模块**解析。生产建议设成绝对路径，如 `/root/uploads` |
| `NOTEPAD_VECTOR_STORE_FILE` | 向量索引文件路径（`./data/simple-vector-store.json`） |
| `NOTEPAD_INDEX_BACKUP_RETENTION` | 索引备份保留份数（`10`） |
| `NOTEPAD_VECTOR_STORE_TYPE` | 向量存储：`simple` / `pgvector`（`simple`） |

#### 仅在 `NOTEPAD_VECTOR_STORE_TYPE=pgvector` 时需要

| 变量 | 说明 |
| --- | --- |
| `NOTEPAD_PGVECTOR_URL` | PostgreSQL 连接串（`jdbc:postgresql://localhost:5433/notepad_vector`） |
| `NOTEPAD_PGVECTOR_USERNAME` | 数据库用户名（`postgres`） |
| `NOTEPAD_PGVECTOR_PASSWORD` | 数据库密码，**无默认值** |
| `NOTEPAD_PGVECTOR_INDEX_TYPE` | 索引档位：`NONE` / `IVFFLAT` / `HNSW`（`NONE`） |

> pgvector 需要一个装了 `vector` 扩展的 PostgreSQL 实例。默认的 `simple` 模式不需要它，也不会创建任何相关连接。

### 2.5 安装并配置 Nginx

1. 从 http://nginx.org/en/download.html 下载 Windows 版 zip，解压到如 `D:\nginx\`；
2. 编辑 `D:\nginx\conf\nginx.conf`，把默认 `server { ... }` 块替换为：

```nginx
server {
    listen       80;
    server_name  localhost;

    root   D:/JAVA-Study/project/notepad/notepadweb/dist;
    index  index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        # 末尾不能加斜杠，否则 /api/notes 会被改写成 /notes 导致 404
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # 必须剥掉 Origin，否则后端那个只放行 localhost 的 CorsFilter 会把
        # 同源 POST 判成非法跨域，登录直接 403（详见 2.7）
        proxy_set_header Origin "";

        # SSE 流式接口（AI 问答、AI 编辑预览）必须关掉代理缓冲，
        # 否则 Nginx 会攒够一整块才转发，前端就不再逐字显示
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_set_header Accept-Encoding "";
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header Origin "";
    }

    client_max_body_size 20m;
}
```

### 2.6 启动

```bash
# 先启动后端（start.bat 或上面的 java -jar）
# 再启动 Nginx
cd D:\nginx
nginx -t          # 检查配置语法
start nginx       # 后台启动
```

浏览器打开 `http://localhost/`。

> Nginx 常用命令：`nginx -s reload`（重载配置）、`nginx -s stop`（停止）。

### 2.7 四个必须知道的坑

1. **后端有 CORS 过滤器，必须让 Nginx 剥掉 `Origin` 头**：

   后端的 `CorsConfig` 只放行 `http://localhost:*` 和 `http://127.0.0.1:*`（给本地开发用），而它在 `/**` 上注册了 `CorsFilter`，**会拦截所有请求**。浏览器的 POST 即使同源也会带 `Origin` 头，于是被判定为非法跨域，**登录接口直接返回 403**。

   前后端同域时后端本来就不需要处理 CORS，在 `location /api/` 里加一行即可：

   ```nginx
   proxy_set_header Origin "";
   ```

   > 症状识别：浏览器 F12 看到 `POST /api/auth/login 403 (Forbidden)`，但用 curl 不带 `Origin` 头请求时正常。

2. **`proxy_pass` 末尾别加 `/`**：
   - `proxy_pass http://127.0.0.1:8080;` → 后端收到 `/api/notes` ✅
   - `proxy_pass http://127.0.0.1:8080/;` → 后端收到 `/notes` ❌ 404
3. **`try_files ... /index.html;` 必须写**：前端用 `createWebHistory()`，不写则刷新子页面 404。
4. **SSE 接口所在的 `location` 必须 `proxy_buffering off`**：AI 问答与 AI 编辑预览是流式的，Nginx 默认会把响应攒够一块再转发，结果就是「前端转半天圈，然后整段答案一次性冒出来」，逐字显示的效果完全失效。同时把 `proxy_read_timeout` 调大（默认 60 秒，长回答会被掐断）。

> 验证是否生效：观察首个 `delta` 到达的时间应明显早于整个响应结束。实测经 Nginx 时首字在总耗时的约 30% 处到达；若被缓冲，首字时间会等于总时间。

## 3. 方案 B：云服务器 Linux（真正上线）

### 3.1 买服务器

1. 阿里云/腾讯云，新手选「**轻量应用服务器**」；
2. 配置建议 **2核2G 起步**，地域选离自己近的；
3. 系统镜像选 **Ubuntu 22.04 LTS**（本指南按此编写）；
4. 设置 root 密码，记下公网 IP。

> 若选 Alibaba Cloud Linux / CentOS，把 `apt` 换成 `yum`，其余一致。

### 3.2 开放端口（两层防火墙都要开）

1. **云控制台「安全组」**：放行入方向 `22`、`80`、`443`（可选）；**不要**放行 8080 和 3306。
2. **系统内防火墙**：见 3.4 第 6 步。

### 3.3 从 Windows 连接服务器

```bash
ssh root@你的公网IP
```

首次提示输入 `yes`，再输密码。连上后提示符变成 `root@xxx:~#`。

### 3.4 装环境

```bash
apt update && apt upgrade -y

# 时区（定时任务按本地时区跑）
timedatectl set-timezone Asia/Shanghai

# JDK 17
apt install -y openjdk-17-jdk
java -version

# MySQL 8
apt install -y mysql-server
systemctl enable --now mysql

# Nginx
apt install -y nginx
nginx -v

# 系统防火墙
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

### 3.5 初始化数据库

```bash

```

在 MySQL 命令行里执行：

```sql

```

建目录、上传 `init.sql` 后执行：

```bash

```

预期能看到 **14 张表**：`user`、`notebook`、`note`、`tag`、`note_tag`、`note_image`、`reminder`、`notification`、`ai_conversation`、`ai_conversation_message`、`ai_answer_feedback`、`ai_rag_eval_case`、`ai_rag_eval_run`、`ai_note_revision`。

> **`init.sql` 与 `sql/upgrade/` 的分工（不要搞混）**
>
> | 场景 | 执行什么 |
> | --- | --- |
> | **全新数据库** | 只跑 `init.sql`。它会自己 `CREATE DATABASE`，并建出**全部**的表、列和索引 |
> | **已有的旧库** | 按 `upgrade/` 里文件名序号**从小到大**执行尚未应用的脚本，**不要**重跑 `init.sql` |
>
> `init.sql` 里没有 `DROP`/`TRUNCATE`，所以在已有库上重跑不会删数据；但它会在第一个「已存在的表」处报 `Table already exists` 并中断，既没有意义也会让人误以为部署失败。
>
> 维护约定：**每次新增 `upgrade/NNN_*.sql` 时，必须同步把同样的改动补进 `init.sql`**，否则新部署的库会缺结构。这一点曾经踩过——`ai_note_revision` 只加在增量脚本里，导致按本文档部署后 AI 编辑功能直接报 `Table doesn't exist`。

> **增量脚本与 jar 的上线顺序：先跑脚本，再换 jar。**
>
> 以 `012_user_token_version.sql`（给 `user` 表加 `token_version` 列）为例：旧 jar 根本不读这一列，先跑脚本完全安全；反过来先换 jar 就会因为列不存在而**所有需要鉴权的接口全部报错**，其中包括登录本身。
>
> 更危险的是把列写成可空：鉴权拦截器每请求都要比对 `token_version`，取到 `null` 会被判定为"token 已失效"，结果是**全站 401、谁都登不进来**。所以该列必须是 `NOT NULL DEFAULT 0`，并且新库走 `init.sql`、旧库走增量脚本，两条路径的列位置也要一致（`012` 用的是 `AFTER status`，`init.sql` 里就插在 `status` 后面）。

> **`013_soft_delete_unique_key.sql` 是数据迁移，不只是结构变更。**
>
> 它把 `notebook.deleted` / `tag.deleted` 从 `TINYINT`（0/1）改成 `BIGINT`（0 正常 / 删除时间戳），并把 `deleted` 收进唯一键 `uk_user_name(user_id, name, deleted)` —— 否则软删之后名字永远无法复用（删掉「工作」就再也建不了「工作」，报的还是误导性的 409「数据已存在，请勿重复提交」）。
>
> 脚本里有 `UPDATE ... SET deleted = UNIX_TIMESTAMP(NOW()) WHERE deleted <> 0` 这段**数据回填**，不能跳过：只改列类型是宽松兼容的（`TINYINT 1` 会原样变成 `BIGINT 1`），但唯一的 `deleted = 1` 会让两行已删除的同名记录在加唯一键时直接撞键。回填后每行的删除时间戳都不同，问题消失。
>
> 这个脚本要和 jar **一起**上线。改列类型本身是向后兼容的（旧 jar 把 `deleted` 当 `Integer`，读时间戳 1789990828 也放得下），真正的问题是**旧 jar 的逻辑删除写的仍然是 `deleted = 1`** —— 在新唯一键 `(user_id, name, deleted)` 下，两行被旧 jar 删除的同名记录会撞键。所以稳妥顺序是：停服 → 跑 013 → 换 jar → 起服。这与 012 的「可以先跑脚本再换 jar」不同。

> **登录失败限流的状态在进程内存里**，重启后端容器即可清空所有计数、解除锁定：
>
> ```bash
> cd /opt/notepad && docker compose restart backend
> ```
>
> 调节阈值用环境变量：`NOTEPAD_AUTH_LOGIN_ATTEMPT_MAX_PER_USER_IP`（默认 5）、`NOTEPAD_AUTH_LOGIN_ATTEMPT_MAX_PER_IP`（默认 50）、`NOTEPAD_AUTH_LOGIN_ATTEMPT_WINDOW`（默认 `15m`，支持 `20s` 这类写法）。**本地联调时所有请求的 IP 都是 `127.0.0.1`，单 IP 兜底会横跨所有测试账号累计**，容易误伤，建议本地把 `MAX_PER_IP` 调大。

> **⚠️ 加环境变量要改两个地方，只改 `.env` 不生效。**
>
> `docker-compose.yml` 的 `backend.environment` 是**显式白名单**：只有列在里面的变量才会传进容器。`.env` 的作用仅仅是给 compose 文件里的 `${...}` 占位符提供取值。
>
> 所以新增一个应用开关要两步：
>
> 1. `deploy/docker-compose.yml` 的 `backend.environment` 里加一行映射，例如
>    `NOTEPAD_XXX: ${NOTEPAD_XXX:-默认值}`（`:-` 给默认值，不配 `.env` 也能跑）
> 2. `deploy/.env` 里写实际取值
>
> **只做第 2 步的话，容器里读到的是空值，而且不会有任何报错** —— 这个坑踩过一次：配了运维账号但容器里是空的，接口全部 403，日志里什么线索都没有。事后用 `docker exec notepad-backend sh -c 'echo $NOTEPAD_XXX'` 才确认。

> **索引备份/恢复接口需要配运维账号，否则一律 403。**
>
> 向量索引是全局单例（一份 `simple-vector-store.json` 服务所有用户），一次恢复会把所有人的检索结果一起回退，所以这几个接口只对运维账号开放。按上面的两步配上：
>
> ```yaml
> # 1. deploy/docker-compose.yml 的 backend.environment（已经预置好，无需改动）
> NOTEPAD_INDEX_ADMIN_USERNAMES: ${NOTEPAD_INDEX_ADMIN_USERNAMES:-}
> ```
>
> ```bash
> # 2. deploy/.env
> NOTEPAD_INDEX_ADMIN_USERNAMES=你的运维账号
> ```
>
> 默认是**空 = 谁都不能用**（fail-closed）。不配的话，`/api/ai/notes/index/backups` 系列会返回 403，而索引状态、重建这些用户级接口不受影响。
>
> 这个变量必须在这几个接口被用到**之前**配好，否则 `backend/scripts/verify-index-backup.sh` 也会全挂在 403 上。

> **换前端产物时不要 `rm -rf` 挂载源目录（踩过）**
>
> `web` 容器把 `./frontend/dist` 挂成了 bind mount。如果先 `rm -rf /opt/notepad/frontend/dist` 再上传新目录，**容器里挂载的仍然是被删掉的旧 inode**，nginx 看到的是空目录，表现为：
>
> ```
> directory index of "/usr/share/nginx/html/" is forbidden      → 首页 403
> rewrite or internal redirection cycle → "/index.html"          → 静态资源 500
> ```
>
> 文件明明在宿主机上，容器里却看不到。两种正确做法：
>
> ```bash
> # 方式一：原地覆盖内容，不删目录本身
> scp -r deploy/frontend/dist/. root@IP:/opt/notepad/frontend/dist/
>
> # 方式二：删了目录就重建容器，让它重新解析挂载点
> docker compose up -d --force-recreate web
> ```
>
> 方式一不需要重启容器，但**旧构建的文件名带 hash，不会被覆盖，会一直堆着**（实测一次部署后从 31 个涨到 48 个）。定期清一次，只留本地这次构建出来的那批：
>
> ```bash
> # 在本地：列出服务器有、本地没有的文件，删掉
> comm -13 <(cd deploy/frontend/dist && find . -type f | sort) \
>          <(ssh root@IP 'cd /opt/notepad/frontend/dist && find . -type f | sort') \
>   | ssh root@IP 'cd /opt/notepad/frontend/dist && xargs rm -f'
> ```

> **向量索引必须挂卷，否则每次重建容器都会丢（踩过）**
>
> `NOTEPAD_VECTOR_STORE_FILE` 默认是相对路径 `./data/simple-vector-store.json`，容器内落点即 `/app/data/`。这个目录**不在** `uploads` 具名卷里，最初版本只挂了 `/app/uploads`，导致每次 `docker compose up -d --build backend` 都会把整个 AI 索引抹掉（`state: NEEDS_REBUILD`，又得重新调一轮 embedding 重建，费时费额度）。
>
> 现在 compose 里已补 `notepad_data:/app/data`，Dockerfile 的 `mkdir -p` 也补了 `/app/data` 并 `chown` 给 `notepad` —— **这一句不能省**：具名卷首次挂载时从镜像该路径继承属主，镜像里没有这个目录的话 Docker 会建成 `root:root`，非 root 运行的应用就写不进去了。

### 3.9 配置 Nginx

```bash
vim /etc/nginx/sites-available/notepad
```

粘贴：

```nginx
server {
    listen 80;
    server_name 你的公网IP;   # 有域名后改成域名

    root /opt/notepad/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        # 末尾不能加斜杠，否则 /api/notes 会被改写成 /notes 导致 404
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # 必须剥掉 Origin，否则后端那个只放行 localhost 的 CorsFilter 会把
        # 同源 POST 判成非法跨域，登录直接 403（详见 2.7）
        proxy_set_header Origin "";

        # SSE 流式接口（AI 问答、AI 编辑预览）必须关掉代理缓冲，
        # 否则 Nginx 会攒够一整块才转发，前端就不再逐字显示
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_set_header Accept-Encoding "";
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header Origin "";
    }

    client_max_body_size 20m;
}
```

启用并重载：

```bash
ln -s /etc/nginx/sites-available/notepad /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

## 5. 常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| SSH 连不上 | 安全组没开 22，或 IP/密码错 |
| 网站打不开、一直转圈 | 安全组没开 80，或 Nginx 没启动 |
| 页面能开但接口报错/404 | `proxy_pass` 末尾多写了 `/`，删掉 |
| 刷新子页面 404 | 少了 `try_files $uri $uri/ /index.html` |
| 图片裂图 | `/uploads` 反代没配，或 `uploads` 目录没权限 |
| 注册收不到邮件 | `MAIL_PASSWORD` 环境变量没设对 |
| 后端起不来 | `journalctl -u notepad` 看日志，多半是数据库密码/连不上 |
| 定时任务时间不对 | 没设时区，补 `timedatectl set-timezone Asia/Shanghai` |

## 6. 安全注意事项

- 生产环境**禁止**把 SMTP 授权码、数据库密码、JWT 密钥写死在代码里——统一用环境变量注入（本文 `systemd` / `start.bat` 方式）；
- 只开放 80/443 到公网，8080（后端）和 3306（MySQL）仅服务器内部访问；
- `JWT_SECRET` 生产环境必须覆盖默认值，且长度 ≥ 32 字符；
- 建议用非 root 的独立数据库账号运行应用（本指南为简化使用 root，正式环境可另建受限账号）。

## 7. 进阶（可选）

### 7.1 绑定域名 + HTTPS

#### 最简单的情况：服务器上只有这一个项目

```bash
# 1. 域名服务商处加 A 记录指向公网 IP
# 2. nginx 的 server_name 改成域名后 reload
dnf install -y certbot python3-certbot-nginx   # 或 apt
certbot --nginx -d 你的域名.com
```

#### 实际情况：和 mall-resume 共用一台服务器

线上的 `clstudy.online` 走的是下面这套，**和上面完全不一样**，照抄上面会踩坑。

**根因**：80 端口只能有一个主人。mall-resume 的商城容器直接绑了 `0.0.0.0:80`，
而它的 `server_name` 是 `_`，于是域名被它兜住 —— 打开 `clstudy.online` 看到的是商城，
不是 404 也不是报错，很容易误判成「域名没生效」。

而且商城的 Nginx 配置**烤在镜像里、没有挂载卷**，没法往它的 `conf.d` 里塞一个虚拟主机。
所以只能从端口层面解：**让商城退到 127.0.0.1:8090，宿主机 Nginx 拿回 80/443 按域名分流**。

```
浏览器
  ├─ http://clstudy.online   ─┐
  ├─ https://clstudy.online  ─┤
  │                           ▼
  │                  宿主机 Nginx (80/443)
  │                    ├ clstudy.online → 127.0.0.1:8082  记事本
  │                    └ 默认 / IP      → 127.0.0.1:8090  商城
  └─ http://47.242.4.27 ─────→ 默认 server → 商城（地址不变）
```

**步骤**：

```bash
# 1. 商城让出 80（改 /opt/mall-resume/.env 的 MALL_PORT=127.0.0.1:8090）
cd /opt/mall-resume && docker compose up -d mall

# 2. 装宿主机入口配置（覆盖掉历史遗留的那份）
scp -i ~/.ssh/id_rsa_aliyun deploy/host-nginx/notepad.conf root@IP:/etc/nginx/conf.d/
#    同时注释掉 /etc/nginx/nginx.conf 里内置的默认 server（root /usr/share/nginx/html），
#    否则 80 端口上两个默认 server，nginx 报 conflicting server name

mkdir -p /var/www/certbot        # ACME 验证文件落点，必须先建
nginx -t && systemctl enable --now nginx

# 3. 证书。用 webroot 而不是 --nginx 插件：插件会去改我们手写的配置，webroot 不碰。
#    ⚠️ PYTHONPATH 不能少 —— 少了 certbot 直接 ImportError
PYTHONPATH=/home/admin/.local/lib/python3.11/site-packages \
  /home/admin/.local/bin/certbot certonly --webroot -w /var/www/certbot \
  --cert-name 你的域名 -d 你的域名 -d www.你的域名

# 4. 安全组放行 443（云控制台）
# 5. 证书就绪后再打开 80 → 301 HTTPS 的跳转，然后 reload
```

**证书没就绪之前，绝对不要先开 301 跳转** —— 443 还不通，跳过去就是打不开，
表现是「域名访问不了」而不是「证书有问题」，很容易查错方向。

**自动续期**：`/usr/local/bin/certbot-renew.sh` + `/etc/cron.d/certbot-renew`（每天 3 点）。
脚本里那行 `export PYTHONPATH=...` 不能删，删了 certbot 就 ImportError，
而 cron 跑的是 `--quiet`，失败没有任何输出 —— 等发现时证书已经过期了。
改完必须跑一次 `certbot renew --dry-run` 确认。

> **两个只有双层反代才会暴露的坑**（都已在配置文件里注释说明）：
>
> 1. **真实客户端 IP 会被吞掉**。容器内 Nginx 原本写的是
>    `proxy_set_header X-Real-IP $remote_addr;`，套上宿主机这层后 `$remote_addr`
>    变成 `127.0.0.1`，把宿主机传来的真实 IP 覆盖了。而后端 `ClientIpResolver`
>    **优先读 `X-Real-IP`** —— 结果是所有访客共用一个限流桶，
>    演示账号连错 5 次就把全站所有人锁在门外。
>    改成透传 `$http_x_real_ip` 即可（空值 nginx 会自动不发这个头，
>    所以直连 `:8082` 时依然正确）。
> 2. **SSE 会被缓冲两层**。容器内那层早就关了 `proxy_buffering`，
>    但宿主机这层默认是开的，AI 问答的「逐字返回」会退化成
>    「转半天圈然后整段答案一次性冒出来」。两层都要关。

### 7.2 后续每次更新如何上线

1. 本地重新 `mvn package` / `npm run build`；
2. `scp` 上传新的 jar 和 `dist`；
3. 重启后端：`systemctl restart notepad`；

## 8. 方案 C：Docker 部署

> **适用场景**：服务器上**已经跑着别的 Docker 服务**，尤其已经有 MySQL 容器。
> 这种情况下不要再装一套宿主机 MySQL 和 Nginx——直接复用现有的，容器间走 Docker 网络通信。

仓库的 `deploy/` 目录就是这套编排，已在阿里云 2 核 2G 的机器上实测通过（与另一套 5 个容器的服务共存，内存 `available` 保持在 500MB 以上）。

### 8.1 关键设计

| 决定 | 原因 |
| --- | --- |
| **复用已有的 MySQL 容器**，不新建 | 小机器上再起一个 MySQL 要 150–500MB，装不下 |
| 后端用 `expose` 而不是 `ports` | 端口 3306/8080 **不对公网暴露**，只有同网络的 Nginx 能访问 |
| 前端映射到 8082 而不是 80 | 80 通常已被现有服务占用 |
| 每个服务都设 `mem_limit` | 不设上限会被 OOM Killer 杀掉 |
| 密钥走 `deploy/.env`，不写进 compose | `.env` 已在 `.gitignore` 里 |

### 8.2 服务器目录结构

```
/opt/notepad/
├── docker-compose.yml        # 来自 deploy/docker-compose.yml
├── .env                      # 真实密钥，只在服务器上，不提交
├── backend/
│   ├── Dockerfile            # 来自 deploy/backend/Dockerfile
│   └── app.jar               # 本地 mvn package 产出后上传
├── frontend/dist/            # 本地 npm run build 产出后上传
└── nginx/conf.d/notepad.conf # 来自 deploy/nginx/conf.d/notepad.conf
```

**服务器上不编译**——不装 Maven、不装 Node，只把本地构建好的产物传上去。1.6G 的机器跑不动构建。

### 8.3 部署步骤

```bash
# 1. 在已有 MySQL 容器里建库、建专用账号（不要用 root 跑应用）
docker exec -i <已有的mysql容器> mysql -uroot -p'<root密码>' \
  -e "CREATE USER IF NOT EXISTS 'notepad'@'%' IDENTIFIED BY '<新密码>';
      CREATE DATABASE IF NOT EXISTS cloud_notepad DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
      GRANT ALL PRIVILEGES ON cloud_notepad.* TO 'notepad'@'%';
      FLUSH PRIVILEGES;"

# 2. 建表（init.sql 自带 CREATE DATABASE 与 USE，新库只跑这一个文件）
docker exec -i <已有的mysql容器> mysql -uroot -p'<root密码>' < /opt/notepad/init.sql
```

本地构建并上传：

```powershell
cd D:\JAVA-Study\project\notepad
mvn -f backend/pom.xml package -DskipTests
npm --prefix notepadweb run build

scp backend/target/notepad-backend-0.0.1-SNAPSHOT.jar root@<IP>:/opt/notepad/backend/app.jar
scp deploy/backend/Dockerfile                          root@<IP>:/opt/notepad/backend/
scp deploy/docker-compose.yml                          root@<IP>:/opt/notepad/
scp deploy/nginx/conf.d/notepad.conf                   root@<IP>:/opt/notepad/nginx/conf.d/
scp -r notepadweb/dist                                 root@<IP>:/opt/notepad/frontend/
```

服务器上写 `.env`（照 `deploy/.env.example`，**六个必填项缺一不可**），然后：

```bash
cd /opt/notepad
docker compose up -d --build
docker compose ps
docker compose logs -f backend      # 看到 Started NotepadApplication 即成功
```

最后在云控制台**安全组放行前端端口**（示例里是 8082）。

### 8.4 小内存机器（2G 以下）的调优

和另一套栈共存时，内存要精打细算。按收益排序：

| 措施 | 省 |
| --- | --- |
| `SERVER_TOMCAT_THREADS_MAX=20`（默认 200，配合 `-Xss256k` 省下大量栈内存） | ~90MB |
| `SPRING_MAIN_LAZY_INITIALIZATION=true` | ~75MB |
| JVM 参数收紧：`-Xmx160m -Xss256k -XX:TieredStopAtLevel=1` | ~60MB |
| journald 限容（`SystemMaxUse=50M`） | ~65MB |
| `vm.swappiness=60`，让 2G swap 真正起作用 | 视情况 |

> ⚠️ **`SPRING_MAIN_LAZY_INITIALIZATION=true` 启用后必须验证向量同步**：
> 改一篇笔记 → 等 15 秒 → 看「AI 索引状态」里的「向量片段」数有没有变化。
> 它可能影响 `@TransactionalEventListener` 的注册。若不同步，删掉这行重启即可（代价是多占约 75MB）。

诊断内存时**看 `docker stats` 而不是 `ps aux`**：`ps` 的 RSS 会把共享库和页缓存重复计算，
实测同一个 MySQL 容器 `ps` 报 523MB 而 `docker stats` 只有 168MB。
